## Sources that could not be read

- Material Design 3 (`https://m3.material.io/components/progress-indicators/guidelines` and `https://m3.material.io/foundations/interaction/states/state-layers`): the pages are script-rendered and `WebFetch` returned only the title. Nothing from M3 is used as a threshold. A `WebSearch` summary (not the page) reported state-layer opacities hover 8%, focus 10%, pressed 10%, dragged 16%, disabled 38%, and a 48dp target; all of these are UNVERIFIED. The rule files therefore do not cite Material Design 3; the Apple HIG, WCAG, MDN and web.dev pages carry the weight instead.
- Material Web component docs (not the M3 guideline page) were read at `https://raw.githubusercontent.com/material-components/material-web/main/docs/components/progress.md` on 2026-10-30: two types (linear, circular), determinate (`value`) or indeterminate, and an `aria-label` for a descriptive name. It carries no when-to-use guidance, so it is cited only for the `aria-label` point.

## UNVERIFIED statements (kept out of thresholds)

- WCAG SC 1.4.1 Use of Color and the NN/g pages on consistency, disabled states and dark mode were not fetched. Statements about them in the rule files are phrased as "check", never as a quoted figure.
- Common breakpoint widths (360, 768, 1280, 1920 px) are the verification widths the user asked for. They are a test matrix, not a source-backed standard; web.dev advises content-driven breakpoints, so the rule tells the reviewer to verify at these widths and place breakpoints where the content breaks.
- The `Skeleton`-to-`motion-reduce` pairing and the `@media (prefers-reduced-motion)` advice for skeletons rest on NN/g's note that skeleton animation can create accessibility problems plus the Tailwind variant docs; no page states the pairing directly.
- Whether Apple HIG Progress indicators page says more than the Loading page was not read (only Loading and Buttons were fetched).
