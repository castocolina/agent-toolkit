# Self-Maintaining Toolkit — Roadmap

**Date:** 2026-10-24 (supersedes the single plan of 2026-10-16, revised through two review rounds)
**Status:** Draft — no plan below has started.

**Goal:** Make `castocolina/agent-toolkit` a self-maintaining marketplace: it installs from this fork, a research skill keeps `skill-judge` aligned with the Agent Skills spec, every skill is judged and fixed to Grade B or better, and a 15-day workflow repeats the cycle and opens PRs.

This file holds what all plans share: order, decisions, global constraints, and who owns which shared interface. Each plan's tasks implicitly include this file's **Decisions** and **Global Constraints**.

## Decisions

User decisions (theirs):

1. Research skill ingests agentskills.io / `agentskills/agentskills` (specification, best practices, optimizing descriptions, evaluating skills, using scripts) and updates `skill-judge` from it. *(Plan 2)*
2. Apply `skill-judge` to every skill, then fix each to Grade B (≥80%) or better, target A (≥90%). *(Plan 4)*
3. Translate all non-Latin script text in skills to English (marp trigger phrases included). Kaomoji are allowlisted. A check blocks new non-Latin script. *(Plans 2, 4)*
4. A workflow runs every ~15 days: refreshes the spec and the rubric, several Copilot models judge with that rubric, one merges and decides whether `skill-judge` or any skill needs updating, then goes skill by skill. *(Plan 5)*
5. When an update is needed, the workflow opens a PR from branch `feat|fix/<yy-mm-dd>-<title-slug>`; the PR body is generated with `commands/explain-pr-changes.md`. *(Plan 5)*
6. Merge knob `AUDIT_MERGE_MODE`: `manual` (default, human review), `auto` (merge when CI is green), `agent` (delegate to GitHub Copilot code review). *(Plan 5)*
7. Evals follow agentskills.io: `evals/evals.json` for output quality, `evals/trigger-queries.json` for activation (should / should-not trigger), executed by `audit.py run-evals`. *(Plans 2, 4, 5)*
8. Copilot model IDs come from repo variables `AUDIT_RESEARCH_MODELS` and `AUDIT_MERGER_MODEL`, chosen in plan 5's spike. *(Plan 5)*
9. Local judges: a native Claude Code Opus subagent and `pi -p --model router-env/my-referee-one`. The Opus judge is a custom agent definition `.claude/agents/skill-judge-opus.md` (`model: opus`, `tools: Read, Grep, Glob`), dispatched natively by the session, so it is read-only by definition (decided 2026-10-24; not headless `claude -p`). Fixers: GLM 5.3 Flash via pi, locally and in the scheduled workflow; if pi cannot run in Actions, stop and ask (no silent substitution). *(Plans 4, 5)*
10. README gives non-interactive install commands per harness and references this fork as the marketplace instead of `softaworks/agent-toolkit`. *(Plan 1)*
11. Skills that cite an inspiration source get that source located, its last update compared with ours, and a recommendation the user decides on: first pass in plan 4, re-checked every scheduled run in plan 5.
12. `explain-pr-changes` takes `--diagrams=none|mermaid|drawio`. Diagram files live on ONE shared branch `pr-diagrams` in folders `<PR number>/`, reused across related/promotion PRs (A→B consolidates several merged PRs, B→C reuses body, images, reviewers and only retitles); the user may delete folders later. *(Plan 3)*
13. `jev-fast-decision` only classifies items and presents them; decisions stay with the user.
14. Upstream PR #48 was closed and `docs/diagram-authoring-rules` deleted (done 2026-10-24).
15. The work is five plans in the order above: README first; the new feature (plan 3) right after the judge so the judge gates the new skill and command.
16. "Skills must have tests" means all three: `evals/evals.json`, `evals/trigger-queries.json`, and a runnable test for any skill that ships `scripts/`. The rubric scores it and `audit.py check` enforces presence. *(Plans 2, 4)*
17. The rubric's Knowledge Delta dimension flags content that current harnesses (Claude Code, Codex, Cursor, opencode, pi, Copilot CLI) already do natively or that current models already know, judged from the judging model's own knowledge; no harness-docs ingest. *(Plan 2)*

Planner calls (mine — check these):

- C1. Default `--diagrams=mermaid` is inline-only (no branch creation, no push), exactly today's behavior; only `drawio` touches `pr-diagrams`.
- C2. Diagram publishing is a new skill `skills/pr-diagrams` (commands cannot ship scripts); the `command-explain-pr-changes` plugin bundles it and `skills/draw-io`.
- C3. Repo tooling is one CLI `scripts/audit/audit.py` plus one test file `scripts/audit/test_audit.py`, Python stdlib only.
- C4. Grades are percentages, so the rubric's total points can change with the spec without breaking thresholds.
- C5. Claude Code-only frontmatter fields (`user-invocable`, `disable-model-invocation`, `argument-hint`) are allowlisted; other unknown top-level fields move under `metadata`, whose values are plain strings.
- C6. Last audited state lives in repo variable `AUDIT_LAST_STATE` (Actions cache evicts entries unused for 7 days < 15) and advances only after a fully successful, durably recorded audit.
- C7. Bot pushes, PRs and auto-merge use secret `AUDIT_BOT_TOKEN`; events caused by `GITHUB_TOKEN` trigger no workflows.
- C9. Synced skills (`gepetto`, `datadog-cli`) are uneditable: `check` reports their issues marked `synced`, `--strict` ignores them, they get no evals, and `run-evals` is never asked to run them.
- C10. `audit.py check --ignore CODE,…` keeps CI green while plan 4 is in flight; plan 4 removes the last ignore.
- C11. A skill still below 80 after the fix rounds blocks plan 4's final PR until the user either approves more rounds or records a waiver in `docs/audit/waivers.json`.

## Global Constraints

- Work happens in worktrees under `.claude/worktrees/<branch-slug>/` (gitignored).
- Skill layout per `AGENTS.md`: `skills/<kebab-name>/SKILL.md` + `README.md`; scripts `#!/bin/bash`, `set -e`, status to stderr, JSON to stdout, cleanup trap.
- `SKILL.md` < 500 lines; frontmatter `name` == directory; `description` ≤ 1024 chars.
- Never delete a skill or any `skills/*/README.md`.
- Never edit `skills/gepetto` or `skills/datadog-cli` (`.github/workflows/sync-*.yaml` overwrites them daily). Findings for them go to `docs/audit/upstream-findings.md` only.
- Do not create `.zip` packages (none exist; the `AGENTS.md` zip rule is stale and out of scope).
- Before EVERY commit that touches `skills/`, `agents/`, `commands/` or `.claude-plugin/`: `python3 scripts/build_plugins.py` and stage `dist/` + `.claude-plugin/marketplace.json` (CI fails otherwise).
- All generated artifacts in English (`AGENTS.local.md`).
- Copied agentskills docs are CC-BY-4.0: keep `SOURCE.json` with repo, commit SHA and license next to them.
- Conventional commit messages; PR bodies via `commands/explain-pr-changes.md`.
- Non-Latin scan scope: every text file under `skills/<name>/` (any extension; files that fail UTF-8 decoding are skipped as binary).
- Agents that run eval prompts or judge skills run with tools restricted to reading (pi: `--tools read,grep,find,ls`; eval runners: `--no-tools`), so action-taking skills (jira, codex, gemini, commit-work…) can never make real calls.
