# Plan 2 — agentskills Ingest Skill and Spec-Aligned skill-judge

> **Layout note (2026-10-25 rework):** eval inputs moved to `evals/files/`, script tests and their fixtures to `tests/skills/<name>/`, and `test_audit.py` plus the stub runner to `tests/audit/`. The file paths in the tasks below are historical.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new maintainer-only `agentskills-research` skill ingests the Agent Skills docs and reference validator from `agentskills/agentskills`, and `skill-judge` is rebuilt on them, with deterministic tooling that validates the judge's output and runs skill evals.

**Architecture:** A bash fetcher copies the upstream docs and validator verbatim into `skills/skill-judge/references/agentskills/`, pinned by commit SHA; docs and validator are tracked independently, so a change to either advances the pin. `skill-judge` reads a machine-parseable `rubric.md` that cites those docs. Judges emit JSON lines; `scripts/audit/audit.py` splits, validates (against the rubric, never against the judge's own numbers), merges with coverage accounting, and runs output and trigger evals through a pluggable stdin/stdout runner that receives the skill under test inline in the prompt.

**Tech Stack:** Bash, Python 3.12 stdlib, `uvx` + `skills-ref` (pinned to the fetched SHA), `jq`, pi (local runner).

**Spec:** [Roadmap](2026-10-24-00-roadmap.md) — Decisions 1, 3, 7, 16, 17; planner calls C3, C4, C5, C9; Global Constraints apply.

Branch: `feat/<yy-mm-dd>-agentskills-ingest-judge`. Depends on nothing; plans 3, 4 and 5 depend on it.

## Review Focus

1. Spec fetch fails mid-way (network, an HTTP 404 that `curl` would otherwise save as the file body, an unknown ref whose `git ls-remote` exits 0 with no output, a missing file, or the publish step itself) → previously stored references and `SOURCE.json` stay byte-identical. Pinned in Task 1.
2. Only the upstream validator changes, a refresh was interrupted before the rubric was updated, or a published reference file was deleted or edited locally → the next fetch still reports work to do (a missing or edited file is restored), and a stale rubric whose rules moved gets a `rubric_version` bump. Pinned in Tasks 1 (fetcher) and 1 Step 5 (`stale-rubric` eval).
3. A judge emits malformed JSON, a non-object, a traversal `skill` name, NaN, scores outside the rubric's `max`, an inflated `max`, a wrong total/percent/grade, or a stale `rubric_version`/`spec_sha` → verdict rejected or skipped, never written outside the judge dir, never merged. Pinned in Tasks 3 and 4.
4. A skill ends up with fewer valid verdicts than `--min-judges` → reported `UNJUDGED` or incomplete, merge exits 2 unless explicitly allowed. Pinned in Task 4.
5. An eval prompt for an action-taking skill (jira, codex, gemini, commit-work) → the runner has no tools, MCP, extensions or skills and runs in an empty sandbox cwd, so nothing real happens; the exact flags are asserted. Pinned in Task 5.
6. A grader answer that is valid JSON but omits, duplicates or invents assertions → harness error, never a passing summary. Pinned in Task 5.
7. A synced skill (`gepetto`, `datadog-cli`) is passed to `run-evals`, or has a critical/high finding → skipped; findings land only in `docs/audit/upstream-findings.md`; never sets `needs_update`. Pinned in Tasks 4 and 5.
8. An eval file shaped like the upstream agentskills.io format (integer `id`s, no `expected_output`) is accepted; an `id` that is absolute or contains `..` is rejected before anything is written. Pinned in Task 5.
9. A trigger answer that is malformed JSON, lacks `skill`, has a wrong type or names an unknown skill → harness error, never a "not this skill" pass. Pinned in Task 5.
10. The runner hangs past the timeout or cannot be launched → harness error (exit 2), not a quality failure (exit 1). Pinned in Task 5.

Run from the repo root.
- Resolution: `resolved` = `AGENTSKILLS_SHA` if set (used as given), else the first field of `git ls-remote https://github.com/agentskills/agentskills refs/heads/<ref>`; when that output is empty (an unknown ref exits 0 with no output) or the sha does not match `^[0-9a-f]{40}$`, exit 1 before touching anything. Every file is downloaded with `curl -fsSL` (`-f` makes an HTTP error exit non-zero instead of saving the error body) from `$AGENTSKILLS_RAW_BASE/<resolved>/<upstream path>` (default base `https://raw.githubusercontent.com/agentskills/agentskills`), so content and recorded SHA always match; any non-zero `curl` exit aborts the run with exit 1 and no publish.
- Source map (7 tracked files): `docs/specification.mdx` → `specification.md`; `docs/skill-creation/<page>.mdx` → `<page>.md` (5 pages); `skills-ref/src/skills_ref/validator.py` → `skills-ref-validator.py.txt`. Docs and validator are compared independently. `changed` names every file whose staged bytes differ from its `SOURCE.json` hash, whose dest file is missing, or whose dest file's hash differs from its `SOURCE.json` hash (a deleted or locally edited reference is restored from the staged copy and reported as changed). A missing `SOURCE.json` makes all seven `changed`.
- Attribution header, the exact first line of every written file followed by one blank line: `<!-- Source: https://github.com/agentskills/agentskills (CC-BY-4.0), verbatim copy, see SOURCE.json -->` (for the `.txt` validator the line starts `# Source:` and has no `<!-- -->`). It contains no SHA or date, so it is constant. `files["<name>"]` in `SOURCE.json` is the sha256 of the written file (header + upstream bytes), which makes unchanged docs byte-identical across SHAs.
- `SOURCE.json`: `{"repo":"agentskills/agentskills","ref","sha":"<pinned sha>","fetched_at":"<ISO8601>","license":"CC-BY-4.0","files":{"<name>":"<sha256>"}}`, rewritten only when `changed` is non-empty. `sha` in stdout and `SOURCE.json` is the SHA the references are pinned at: `resolved` when `changed` is non-empty, else the previously recorded SHA. Every `uvx … skills-ref@<sha>` pin and the rubric's `spec_sha` use this value.
- `rubric_stale` = true when the `spec_sha:` line in the rubric file differs from the pinned `sha` or the rubric file is missing. It is computed on every run, including unchanged ones, so an interrupted refresh (references published, rubric not updated) is detected on the next run.
- Publish is all-or-nothing: copy current dest files and `SOURCE.json` to `$STAGE/backup/`, move changed files in, write `SOURCE.json.tmp` and `mv` it last; on any failure restore from the backup and exit 1. Test hook: `FETCH_SPEC_FAIL_AT=metadata` makes the run fail after the files are moved and before `SOURCE.json` is replaced.

- `audit.py merge --in DIR --out DIR --judges m1,m2 [--skills x,y] [--check FILE] [--waivers FILE] [--min-judges N] [--allow-incomplete] [--rubric FILE] [--upstream-findings FILE]` (`--rubric` default per Task 3 `rubric-check`; `--upstream-findings` default `<root>/docs/audit/upstream-findings.md`). `--judges` takes model IDs and slugs them; `--skills` defaults to every `skills/*/`; `--min-judges` defaults to 1. Writes `merged.json` `{"rubric_version","spec_sha","complete":bool,"skills":[{"name","percent":float|null,"grade":"A|B|C|D|F|UNJUDGED","judges":{slug:percent},"missing_judges":[…],"disagreement":bool,"synced":bool,"waived":bool,"skills_ref_valid":bool|null,"check_issues":[…],"findings":[…]}],"needs_update":bool}` and `report.md` (summary table, Disagreements, Missing verdicts, Below target, Waived, Synced: names only, pointing at the upstream-findings file). Rules:
  - `complete` is true iff every selected skill has at least `--min-judges` valid verdicts from the `--judges` list. A judge without a valid verdict is always listed in that skill's `missing_judges`, but only affects `complete` when it pushes the count below `--min-judges`.
  - percent = `round(mean of valid verdict percents, 1)`; grade = the Task 2 thresholds applied to that rounded mean (A ≥ 90, B ≥ 80, C ≥ 70, D ≥ 60, else F), never an average of the judges' grades; no valid verdict → `UNJUDGED`; `disagreement` when percents differ by > 10; findings deduped on `(dimension, file, fix lowercased)`.
  - Synced skills (roadmap: findings for them go to `docs/audit/upstream-findings.md` only): their `merged.json` entry has `synced: true`, empty `findings` and `check_issues`, `skills_ref_valid: null`; their findings and check issues are appended to the `--upstream-findings` file under a heading naming the `--out` directory, and appear nowhere in `merged.json` or `report.md`. They never feed `needs_update`.
  - `check_issues` are copied from the skill's `--check` entry (ignored issues keep their `ignored` flag). `skills_ref_valid` is derived, never read (the `check` output has no such field): `false` when the entry has an issue with `code == "skills_ref"` and `ignored == false`; `true` when the entry exists and has none (an ignored `skills_ref` issue, or any other code such as `missing_evals` or `non_latin`, does not make it false); `null` when there is no `--check`, or the skill is absent from the check file (then `check_issues` is `[]`). `waived` is true when `--waivers` (`[{"skill","percent","reason","date"}]`) holds an entry whose `skill` equals the name and whose `percent` is <= the skill's current percent (a skill that dropped below its waived score, or is `UNJUDGED`, is not waived).
  - `needs_update` = any non-synced, non-waived skill that is below 80 or `UNJUDGED` (percent `null` counts as below target), or any critical/high finding on a non-synced skill, or any non-ignored `check_issues` entry on a non-synced skill. A waiver suppresses only the "below 80" condition: a waived skill's critical/high findings and non-ignored check issues still set `needs_update`.
  - Exit 2 when not `complete` unless `--allow-incomplete`.
