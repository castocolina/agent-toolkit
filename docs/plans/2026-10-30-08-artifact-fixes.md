# Plan 8 — Fix Skills, Commands and Agents in Small Batches

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every skill, command and agent grades 90 or more under its judge profile, with passing evals, and the known issues in sections 1-5 of the ledger are closed or explicitly waived, without any agent holding more than a few artifacts at once and without a tail of findings left for the end (the plan 4 failure: one high-only wave, 359 findings left).

**Architecture:** A generator turns the merged verdicts into an ordered queue of small batches (at most 3 artifacts and 15 findings each, lowest score first) and writes one brief per batch. One loop runs per batch: fix by artifact, judge, evals, scope check, commit, mark closed. The next batch starts only when the previous one is closed. Anything not fixed after three rounds is re-queued as its own single-artifact batch, never parked. The queue file is the resume point.

**Tech Stack:** `scripts/audit/audit.py`, `skills/skill-updater` (plan 6), pi lanes, `build_plugins.py`.

**Spec:** [Known issues](2026-10-30-00-known-issues.md), plan 4 merged verdicts (`docs/audit/2026-10-28/merged.json`), [Plan 7 disposition](2026-10-30-07-artifact-audit.md) output, user rulings of 2026-10-30 (batches, no leftovers); Roadmap Global Constraints apply.

Branch per PR: `fix/<yy-mm-dd>-artifact-fixes-<n>`, one PR per four closed batches (about 12 artifacts), each with its own dual review. Depends on plans 6 and 7.

## Global Constraints

- As plan 6, plus the rules below.
- **Batch size:** at most 3 artifacts and 15 findings per batch, where the count is every finding of every severity in the latest merged verdict at generation time (lows included, nothing conditional), and the brief lists exactly those findings. An artifact with more than 15 findings is its own batch and is dispatched in passes of at most 15 findings (critical, high and D7/D8 findings first, then the rest in report order). Ruling: lows always count and always go into the brief, because "which lows still matter once the mediums are fixed" is only known after fixing, and the roadmap leaves no findings over.
- **Finding identity:** a finding is identified by `(artifact, dimension, file, fix.lower())`, the dedup key `merge` already uses plus the artifact. Verdict ids (`D7-1`) repeat across artifacts and are reassigned on every re-judge, so they appear in briefs as labels (`<artifact>#<id>`) and never as an identity; waivers and `check` use the key.
- **One dispatch per artifact**, never per batch: an implementer sees one artifact's findings (at most 15 per dispatch, the batch cap), commits after every step, and ends with the report file.
- **Closing a batch** needs all of: both lanes re-judge every changed artifact at 90 or more with no high finding; every medium-or-higher finding in the latest verdict is absent or waived with a reason in `batches.json` (`batches waive`, at close time); evals at 90 percent or more for each changed skill and each changed command, run with `--fail-under 0.9`; `check --strict` clean; the scope check passes; committed. A low that survives on an artifact at 90 or more does not block closing: `batches check` prints it as a residual low and Task 7 reports the total (Ruling: judges re-rate lows every round, so blocking on them never converged in plan 4; lows are still in every brief and are attempted). A command with no eval file cannot close: its first dispatch adds `commands/evals/<name>.json` as its own commit before any other edit (Ruling: so the command gate always has a file to run; Task 5 Step 1). No batch starts while the previous one is open.
- **Rounds:** at most 3 fix rounds per batch (rounds 1-2 resume the implementer, round 3 uses a more capable model). Findings still open after round 3 move to a new single-artifact batch placed first in the queue, which starts at `rounds` 0 with its own three rounds; an artifact may be re-queued twice, then the user decides (waive or stop). Ruling: the new batch restarts its round count, because `requeues` (at most two) already bounds the total at nine rounds per artifact. Nothing is left for "the end".
- **Scope-check base:** record `BASE=$(git rev-parse HEAD)` before each batch; the check is `git diff --name-only $BASE...HEAD` against this allowlist: each batch artifact's own paths (`skills/<name>/`, or `commands/<name>.md` with `commands/evals/<name>.json` and `commands/evals/files/`, or `agents/<name>.md`), `tests/skills/<name>/` for each batch skill (Step 3 may fix script tests), `docs/audit/evals/<name>/` for each batch artifact (`run-evals` summaries), `dist/`, `.claude-plugin/marketplace.json`, and the queue bookkeeping, `docs/audit/batches.json` and everything under `docs/audit/batches/` (briefs, including the one `requeue` writes, and each round directory `<id>/r<round>/` with its verdicts, `merged.json` and `report.md`). It fails on `skills/gepetto`, `skills/datadog-cli` or anything else.
- `delete`, `convert-to-skill` and `merge-into` dispositions run only with the user's recorded answer from plan 7 Task 3; those artifacts are not queued until then.
- Generation rules for diagrams live in `mermaid-diagrams` and `draw-io`; `commands/explain-pr-changes.md` keeps only a pointer and a minimal fallback and stays source-agnostic.
- Eval fixtures: a scenario that needs a file, code or deck is given a fixture under `evals/files/` and passes it via `files`; the runner has no tools by design.

## Review Focus

1. A fix lowers another dimension (plan 4: a high wave broke evals) → each batch re-judges and reruns evals for exactly the artifacts it changed before it closes. Pinned in Task 3 closing steps.
2. A batch is too large and the agent drops findings → the generator enforces the caps and a test checks no batch exceeds them. Pinned in Task 1.
3. An eval is loosened to pass → each batch commit lists assertion changes as clarification, restoration or loosening, and a loosening needs a stated reason. Pinned in Task 3.
4. Findings are silently left behind → `batches.json` has no artifact with unwaived medium-or-higher findings, or without a verdict, in a closed batch (a check script enforces it), and unresolved findings re-queue. Pinned in Tasks 1 and 3.
5. The command eval gate is skipped → the `explain-pr-changes` gate (every id in its eval file at run time) runs once in Task 4 and must be 100 percent. Pinned in Task 4.
6. A synced skill or an out-of-scope file is edited → the scope check in every batch and in Tasks 4-6. Pinned in Task 3 Step 6 and the scope steps of Tasks 4, 5 and 6.

### Task 1: Batch generator in `audit.py`

**Files:**
- Modify: `scripts/audit/audit.py`, `tests/audit/test_audit.py` (new class `BatchTests`)
- Create: `docs/audit/batches.json` and `docs/audit/batches/` (output, committed; the only bookkeeping paths, so the scope allowlist names exactly these two)

**Interfaces:**
- Consumes: one or more `merged.json` files exactly as plan 5 `merge_verdicts` writes them: the top-level `skills` array, one entry per artifact with `name`, `percent` (one-decimal number, or null when unjudged), `synced` and `findings[]` (`id`, `severity`, `dimension`, `file`, `line`, `fix`); other keys are ignored (Ruling: a number, not an integer, because `merge` averages verdicts: `92.8` in plan 4's file); `audit.py artifacts` for kinds.
- Produces: `audit.py batches generate --merged FILE[,FILE] --out docs/audit --max-artifacts 3 --max-findings 15 [--exclude NAME,...]` writes `docs/audit/batches.json`, an array whose order is the queue order (`[{id, artifacts: [{kind, name, percent, findings: {critical, high, medium, low}}], brief: "docs/audit/batches/NN-<names>.md", status: "queued"|"open"|"closed"|"requeued", rounds: int, requeues: int, waived: [{artifact, dimension, file, fix, reason}]}]`, `requeues` 0 at generation) and one brief per batch (per finding: label `<artifact>#<verdict id>`, severity, dimension, `file:line`, fix text; no prose added). Queue predicate (the only definition): an artifact is queued iff it is not synced, not excluded, and (`percent < 90`, a null `percent` counting as under 90, or it holds a `critical` or `high` finding). Round `<round>` of batch `<id>` lives in `docs/audit/batches/<id>/r<round>/`: verdicts under `judgements/<slug>/<name>.json`, plus the `merged.json` and `report.md` that `merge --out` writes there. When `batches.json` already exists, `generate` preserves every existing entry with its `id`, `status`, `rounds`, `requeues` and `waived`, and appends batches (new ids after the highest used) only for artifacts not present in any existing entry; a missing file is written whole. `finding_key(artifact: str, finding: dict) -> tuple` returns `(artifact, dimension, file, fix.lower())`. Operations: `batches set --id N --status S` updates a status. `batches waive --id N --merged FILE[,FILE] --artifact NAME --dimension D --file F --reason R` appends a `waived` entry (full key, with the `fix` text read from the latest verdict) for every finding of NAME matching dimension and file; exit 2 when nothing matches or the reason is empty. `batches requeue --id N --artifact NAME --merged FILE[,FILE]` removes NAME from batch N and creates a new single-artifact batch (next unused id, status `queued`, `rounds` 0, `requeues` = N's value + 1, findings and brief from the latest verdict) inserted immediately before the first `queued` entry of the file, i.e. the head of the queue; batch N becomes `requeued` if it is left with no artifacts; exit 2 for an unknown id or an artifact not in batch N, exit 3 with nothing written when `requeues` would reach 3 (the user decides: waive or stop). `batches check --merged FILE[,FILE]` (the flag is required; later files win per artifact) exits 1 when, for any batch with status `closed`, an artifact has no verdict in the given files, scores below 90, or has a critical, high or medium finding in its latest verdict whose key is not in that batch's `waived`; it prints each surviving low as `residual low` without failing; batches that are `queued`, `open` or `requeued` are not checked.

**Interfaces:** Consumes `batches.json` and the batch brief. Produces a closed batch: commits, a re-judge verdict, a status update.
