# Plan 13 — skill-judge Flags Unexplained Removals and Checks Sources on Every Judgment

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On every judgment for which a previous version can be read (every prompt `judge-prompt` builds, and every direct judgment inside this repository by a judge that can run commands), skill-judge sees what the previous version of the artifact held and reports, as a high finding, every rule, step, fact, template, example, paragraph, line or file that is gone without a recorded reason, including collateral deletions next to an intended edit. It also checks what the artifact states and references against what it can read, and its fixes never advise deleting content without naming where that content goes. Fixers (plan 14, plan 9, the scheduled audit) get one written rule set and one record format. The scheduled audit does not turn this into mass findings before plan 14 has recovered each artifact.

**Why:** Plans 4 and 8 rewrote most artifacts to satisfy the judge, and much guidance was lost (measurements in [plan 14](2026-11-06-14-content-recovery.md), Inputs). The cause is the rubric: it says "Redundant: the model certainly knows it. Delete" and "The Tutorial ... Fix: delete", and nothing weighs against deletion, so fixers raised scores by cutting. The judge never sees the previous version, so it cannot notice a loss. User rulings R3, R5 and the judge half of R4 ([intent](2026-11-06-13-content-recovery-intent.md)) put this check in skill-judge itself.

**Architecture:** `audit.py judge-prompt` gains a previous-version digest (section list, removed paragraphs and lines, removed or reduced non-markdown files, and the path of the artifact's removal record), built from a git ref or a directory. Rubric v5 turns each unexplained digest item into a high D1 finding and adds source checks; the skill-judge protocol runs both on every judgment. `docs/audit/fixer-rules.md` holds the fixer rules and the record format that explains a removal. The scheduled audit builds its judge prompt through `judge-prompt`, with a gate that defers the removal check for each artifact until its plan 14 recovery batch closes. Calibration proves v5 lowers no correct grade. Registry rows for commands and agents become valid, so plan 14 and the v5 source check can use them.

**Tech Stack:** `scripts/audit/audit.py` (`judge-prompt`, `validate_entry`, `ours_updated`), `skills/skill-judge`, `skills/skill-updater`, `.github/workflows/skill-audit.yaml`, `tests/skills/skill-judge/calibrate.sh`, pi referee lanes, `build_plugins.py`.

**Spec:** this file, [intent](2026-11-06-13-content-recovery-intent.md) (R3, R5, R6, the judge half of R4, and the standing rulings), Roadmap Global Constraints, plan 12 calibration criteria.

Branch: `feat/<yy-mm-dd>-judge-preservation`, one PR with its own review. `<wt>` everywhere in this plan is the absolute path of the git worktree that has this branch checked out (`git rev-parse --show-toplevel` run inside it). ## Global Constraints

- **Never delete to raise a score.** A removed rule, step, fact, template or example needs a recorded decision (Task 4 record format). This applies to every edit in this plan: Task 6 renders the digest of this plan's own changes to skill-judge and skill-updater and records each listed item.
- **Credits are provenance.** Never remove, shorten or reword a credit, attribution or license line (standing ruling). Rule 5 of `skills/skill-judge/references/judge-prompt.md` stays word for word.
- **Lanes:** two referee lanes per judging, calibration or review round is ideal, and one is enough; a third replaces an unavailable one. Lanes are not blockers: pivot or wait, never stop the plan (standing ruling 2026-11-04/05, recorded in the intent file). This overrides plan 12's "stop with fewer than two lanes".
- **Implementers:** native sonnet subagents (Claude Code `Agent` tool, `model: "sonnet"`, `effort: "medium"`), one per task. `router-env/my-coding` is not used. Review and judging run only on referee lanes, never on native Opus.
- **`dist/`:** every commit that changes `skills/skill-judge/` or `skills/skill-updater/` first runs `python3 scripts/build_plugins.py` and includes `dist/` (`dist/plugins/skill-judge` mirrors skill-judge, and `main.yaml` fails when `dist/` is out of date).
- **Shell rules:** no `cd` chains, no heredocs, no multi-statement one-liners; scripts are written with the Write tool and run with `bash /abs/path.sh`; commit with `git -C <wt> commit -F <file>`; no attribution trailers. Pass these rules to every subagent.
- **The old text is never sent whole** to a judge: only the digest (headings with first lines, removed units cut at 300 characters, file names with line counts).

### Task 1: Previous-version digest in `judge-prompt`

**Files:**
- Modify: `scripts/audit/audit.py` (helpers below, `render_judge_prompt`, the `judge-prompt` parser), `tests/audit/test_audit.py` (new class `DigestTests`; the existing `JudgePromptTests` stay green with no assertion changed, per Step 1 (h2)).

**Interfaces:**
- `norm_tokens(text: str) -> list[str]`: lowercase `\w+` tokens. `shingles(text: str, n: int = 5) -> set[tuple[str, ...]]`: the n-token windows of `norm_tokens(text)`.
- `digest_units(text: str) -> list[str]`: the units of one markdown file. A prose paragraph (a blank-line-separated block) is one unit; inside a list or a table, each list item (with its continuation lines) and each table row is its own unit; a fenced code block is one unit; headings are not units (the section list covers them). Units under 3 words are skipped.
- `unit_id(text: str) -> str`: `para:` plus the first 8 hex digits of the sha256 of `" ".join(norm_tokens(text))`.
- `artifact_snapshot(root: Path, kind: str, name: str, src: str | None) -> dict[str, bytes] | None`: repo-relative path to content for the artifact's files: everything under `skills/<name>/` except `evals/` for a skill (eval assertion changes are governed by plan 8's loosening rule, not by the digest) and, for `skill-judge`, except `references/agentskills/` (the vendored upstream spec mirror: upstream text, not ours, ruling R6), the single file `commands/<name>.md` or `agents/<name>.md` otherwise. `src` is None (working tree), a git ref (`git ls-tree -r --name-only` and `git show <ref>:<path>`), or a directory holding the previous copy at paths relative to the artifact root (a skill's directory contents, or the single `<name>.md`). `src` is a directory when it names an existing directory (a relative path resolves against the current working directory, as shell paths do); anything else is a git ref. Returns None when the ref or directory does not resolve, the root is not a git repository (for a ref), or the artifact does not exist there.
- `removed_units(prev: dict, cur: dict) -> list[dict]`: `{id, path, text}` for every unit of every previous `*.md` file that is removed, uncapped, longest first. A unit of 5 or more words is removed when fewer than half its shingles appear in the union of the shingles of every current file (markdown or not). A unit of 3-4 words is removed when its normalized text appears in no current file.
- `removed_files(prev: dict, cur: dict, threshold: float = 0.5) -> list[dict]`: `{path, status, lines, kept}` for every previous non-markdown file that is absent now (`deleted`; a file that is not valid UTF-8 is reported `deleted` with `lines: null`), or present but with fewer than `threshold` of its non-blank lines (stripped) present as lines in the current file (`changed`). A file that is not valid UTF-8 in either version and is present in both is `changed` with `lines: null` and `kept: null` when its bytes differ, and is not reported when they are equal. Smaller edits inside scripts are left to code review and the script tests; plan 14's inventory passes `threshold=1.0` to list any line lost.
- CLI: `audit.py judge-prompt --kind K --artifact PATH [--artifact PATH ...] --judge SLUG [--previous SRC ...] [--recovery-gate QUEUE] [--digest-dir DIR]`.

**Digest block** (one per artifact and `SRC`, in `--previous` order):

```text
=== previous-version digest: <name> at <SRC> ===
sections:
- <path>: <heading> | <first non-empty line under it, cut at 120 characters>
removed units (<total>, showing <shown>):
- para:<id> <path>: <unit text, cut at 300 characters>
removed or reduced files:
- file:<path> deleted (<lines> lines) | file:<path> changed (<kept>/<lines> lines kept)
record: <absolute path of docs/audit/recovery/<name>/record.md> | record: none
```

`<SRC>` is printed as given on the command line. At most 40 removed units are shown; when there are more, `<total>` says so and the judge reports that the list was cut. Empty lists print `- none`. A file with `lines: null` prints `deleted (binary)` or `changed (binary)`. Only `para:` and `file:` lines are items the judge must explain; `sections:` lists the previous version's headings only and is context (where a unit sat; the judge compares it with the current headings it reads in the files to see whether a heading was only renamed), never an item by itself: a section that is gone shows up through its units.
