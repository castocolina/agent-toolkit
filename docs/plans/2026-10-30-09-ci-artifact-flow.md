## Global Constraints

- Everything in plan 5's Global Constraints still applies: keyless gates that run no PR code, trusted copies of tooling, step-scoped tokens, state written only by plan 5's `attempt`, `checkpoint` and `state` jobs, review off unless `AUDIT_REVIEW_MODEL` is set.
- A model knob names an explicit model ID or `auto`, and the model used is recorded in the PR; there is no `family:<name>` resolution. Ruling: this plan follows plan 11's scope cuts (family resolution, jev and `JEV_API_KEY`, skill install, automerge, `re_review=no`, upstream `pr` mode), because it depends on plan 11 and the cuts are plan 11's recommended default. If the user declines a cut, the matching line here is re-reviewed against the restored plan 5 Phase 2 rule.
- No step calls jev; the orchestrating agent decides.
- No workflow step edits a synced skill.

## Review Focus

1. Stage 1 changes the pinned spec and stage 2 judges against the old pin → stage 2 starts from the pin stage 1 produced, or from the committed one when stage 1 made no change. Pinned in plan 11 Task 3 (B3); checked in Task 1.
2. A new artifact kind widens what a model can edit → the scope check allowlist names kinds explicitly and the fixer may only touch the artifacts the decision lists. Pinned in Task 2.
3. The matrix explodes in cost, or the same artifacts are picked every run → a per-run cap `AUDIT_MAX_ARTIFACTS` (default 10) on the rotation and a cursor in the audit state that only `state` advances (Step 3a item 7), so it moves by the cap exactly when `state` writes. The cap never bounds `detect`'s own full set (spec, judge or state change, `force`; plan 11 cuts `re_review=no`). Pinned in Task 2.
4. The model-validity pass edits rules automatically → it only produces proposals in the PR body. Pinned in Task 2.
5. The review job approves its own judge change → a PR that changes `skills/skill-judge/**` always requires a human, regardless of `AUDIT_ON_POSITIVE`. Pinned in Task 3.

Ruling: workflow level, because step `env` does not cross steps.
- Produces: `select-artifacts.py --max N --kinds K --cursor C` prints `{"selected": [{kind, name, path}, ...], "next_cursor": int}`: artifacts of the allowed kinds, synced skills (`gepetto`, `datadog-cli`) excluded, sorted by kind then name, N of them starting at C and wrapping; exit 2 when one name appears under two kinds, because verdict files are keyed by name. **Judged-set contract** (defined only here): the `detect` job publishes `skills` = the sorted union of `audit.py detect`'s `skills` and the `selected` names of kind `skill`; `others` = the `selected` entries of kind `command` or `agent` (`[]` when none); `next_cursor`; and `run_needed` = `true` when `audit.py detect` says so or `skills` or `others` is non-empty (reason `rotation` added). Rotation skills join `skills`, so every Phase 1 reader of `needs.detect.outputs.skills` covers them unchanged; only the readers in Step 3a learn `others`. **Target encoding** (defined only here): a decision target is a string: a skill's directory name (Phase 1), `command:<name>` (`commands/<name>.md`) or `agent:<name>` (`agents/<name>.md`), `<name>` matching `[A-Za-z0-9][A-Za-z0-9._-]*`; nothing else is valid. The `targets` sentence of `merge-prompt.md` and `fix-prompt.md` names the three forms (the merger picks the form by which file exists; names are unique across kinds, plan 7 Task 1). `validate-decision` keeps Phase 1's check for a plain string and requires the file for a prefixed one; `--spec-changed` and `--structure-changed` keep their membership tests, because `skill-judge` and `agentskills-research` have only the plain spelling. Ruling: strings, because every Phase 1 reader of `targets` (`validate_decision`, `load_targets`, `pr-body-prompt.py`, the `apply` `jq join`) requires a list of strings, and an object would be a second spelling of a skill. **Scope predicates** (one per mode): `fixer` allows `skills/<n>/**` and `tests/skills/<n>/**` for a skill target (Phase 1), exactly `commands/<n>.md` and `commands/evals/<n>.json` for `command:<n>`, exactly `agents/<n>.md` for `agent:<n>`, and `docs/audit/**`; `review` (no targets) adds `commands` and `agents` to `REVIEW_PREFIXES`; `decision` allows only `decision.json`. Each path is judged alone, so an eval-only diff passes in `fixer` for a listed command and in `review`. Ruling: per path, like Phase 1's `tests/skills/<n>/**`. **No review record:** no workflow step runs `audit.py track`. Ruling: no code reads `last_reviewed` (plan 6 Task 3), `apply` runs only when the decision updates something, and a status derived from `stale` would overwrite a `path-moved` row; the CI's record is `review_cursor`; dates come from `skill-updater` runs (plan 8 Task 6). **Eval-status contract:** `eval-status.sh STATUS1 STATUS2 [STATUS...]` takes two or more statuses (fewer, or a non-integer, still exits 64) and applies its Phase 1 rule over all of them: any 2 exits 2; else the first status other than 0 or 1 is the exit; else `quality_failed=true` when any is 1. Ruling: widen the tested combiner rather than pre-combine in the workflow, because its precedence (harness error over crash over quality failure) is pinned there.
