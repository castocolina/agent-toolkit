# Plan 12 — Pinned Specs and Calibrated Profiles for Commands and Agents

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Commands and agents are judged against their own pinned, refreshable specs, the way skills are judged against agentskills.io, with judge profiles calibrated on two lanes before their scores drive any fix.

**Architecture:** One judge (`skill-judge`) with one profile per kind. `agentskills-research` gains a second fetch script that pins the Claude Code pages that define commands and subagents (URL, sha256, fetch date; no verbatim copy) with one digest per kind, and `rubric-check` fails when a profile or the spec notes no longer match the pin. `docs/audit/artifact-specs.md` is rewritten from the raw pages and is the only record a later refresh compares against. A calibration set judged inside a scratch root (the answer key stays outside the judge's tree and prompt) proves each profile separates good from bad on two lanes. The 13 commands and agents are then judged again into their own directory; that merged file is plan 8's input for commands and agents.

**Tech Stack:** Bash, curl, jq, sha256sum, `scripts/audit/audit.py`, `skills/agentskills-research`, `skills/skill-judge`, pi lanes `my-referee-one|two|three`.

**Spec:** user rulings of 2026-11-02 (below); [Plan 6](2026-10-30-06-new-skills.md) Task 4 (profiles, `artifact-specs.md`); [Plan 7](2026-10-30-07-artifact-audit.md) output in `docs/audit/2026-11-02/` (the uncalibrated baseline and `disposition.md`). Roadmap Global Constraints apply.

Branch: `feat/<yy-mm-dd>-artifact-judge-specs`, stacked on plan 7; plan 8 is stacked on this plan.

**Files:**
- Create: `skills/agentskills-research/scripts/fetch-claude-specs.sh`, `skills/skill-judge/references/claude-code/SOURCE.json`, `tests/skills/agentskills-research/test-fetch-claude-specs.sh`
- Modify: `scripts/audit/audit.py` (`rubric_check`, `render_judge_prompt`), `tests/audit/test_audit.py`, `skills/skill-judge/references/profiles/{command,agent}.md` (front block only), `dist/`

**Interfaces:**
- `fetch-claude-specs.sh [--dest DIR] [--profiles DIR] [--base URL] [--keep] [-h]` (any other argument exits 2 with usage): creates its temp directory with `mktemp -d`, resolves it with `realpath`, and exits 1 before downloading when it lies inside `git rev-parse --show-toplevel` or inside the main checkout (the parent of `git rev-parse --path-format=absolute --git-common-dir`); downloads `skills`, `sub-agents` and `plugins-reference` from `--base` (default `https://code.claude.com/docs/en`); rejects an empty body, or one whose first non-blank line starts with `<!doctype` or `<html` (case-insensitive), with exit 1; computes per-kind digests, each the sha256 of its pages' `"<page> <sha256>\n"` lines sorted with `LC_ALL=C` (command ← `skills`, `plugins-reference`; agent ← `sub-agents`, `plugins-reference`); when every page hash equals the pin it leaves `SOURCE.json` untouched (including `fetched_at`), otherwise writes `{"base", "fetched_at", "pages": {"<page>": {"url", "sha256"}}, "digests": {"command", "agent"}}` atomically (temp file plus `mv`; the old file survives any failure); prints `{changed: [pages], unchanged: [pages], digests, profiles_stale: [kinds whose profile source_digest differs from digests[kind]]}`. `--keep` leaves the pages in that checked temp directory and adds its path to the JSON as `kept`; without it the directory is removed on exit. `--profiles` defaults to `DEST/../profiles`.
- Profile front block: the first two lines are exactly `profile_version: <int>` and `source_digest: <64 hex>`, then one blank line, parsed with the strictness of `load_rubric`. `rubric_check` checks profiles only when `references/profiles/*.md` exist: a profile without the block, or with a `source_digest` that differs from `claude-code/SOURCE.json` `digests[<kind>]`, is a reason naming the profile; profiles present but `claude-code/SOURCE.json` missing is a reason. `render_judge_prompt` strips the block when present and leaves a profile without one unchanged (the copy the judge reads from disk keeps it; harmless).

### Task 3: Calibrate the profiles on two lanes

**Files:** Create `tests/skills/skill-judge/calibration/{commands/cal-a.md,commands/cal-b.md,commands/evals/cal-a.json,commands/evals/cal-b.json,agents/cal-c.md,agents/cal-d.md}`, `tests/skills/skill-judge/calibration/expected.json`, `tests/skills/skill-judge/calibrate.sh`, `tests/skills/skill-judge/test-calibrate.sh`, `docs/audit/<date>-calibration/` (verdicts, `calibration.md`).

**Interfaces:**
- `calibrate.sh [--verdicts DIR] MODEL...` where each MODEL is a lane model id such as `router-env/my-referee-one`. Normal mode builds a scratch root with `mktemp -d` holding only `skills/skill-judge/`, `docs/audit/artifact-specs.md` and the calibration `commands/` and `agents/` trees (never `expected.json`); per file and lane it runs `audit.py --root <scratch> judge-prompt --kind <kind> --artifact <scratch absolute path> --judge "$(audit.py slug MODEL)"`, pipes it into the `audit.py pi-cmd judge --model MODEL` command started with the scratch root as its working directory (the read tools are not sandboxed; keeping the answer key out of the judge's tree and prompt is the isolation this plan claims), captures stdout with `audit.py split-verdicts --judge MODEL --out docs/audit/<date>-calibration/judgements`, and validates each verdict; a harness failure (no valid verdict) is retried once; fewer than two lanes with valid verdicts for every file exits 1. `--verdicts DIR` skips dispatch and scores an existing `<slug>/<stem>.json` tree.
- Scoring against `expected.json`: per file a band (`>=90` or `<60`) and, for bad files, defects `{id, file, dimension, lines: [first, last] | null, rule}` (`rule` quotes the profile or rubric line it breaks). A finding detects a defect when its `file` (scratch-root relative) and `dimension` are equal and its `line` lies in `lines`, or `lines` is null (an absent feature: any line, including null). One finding may detect several defects of the same file and dimension. Pass per round: on both lanes good files at 90 percent or more and bad files under 60 percent; per bad file at least 80 percent of its defects detected on at least one lane; a lane gap over 10 percentage points on a file is reported, and fails the round only when it comes from D4, D5, D7 or D8.
- `test-calibrate.sh` (run by `scripts/audit/run-script-tests.sh`, which runs every `tests/skills/*/test-*.sh`): replay mode with stub verdicts (a wrong-file finding with the right dimension and line detects nothing; a null-line finding detects a `lines: null` defect; band thresholds, the 80 percent rule and the gap rule; an invalid verdict is reported), and normal mode with a stub `pi` first on `PATH` that records its working directory, arguments and stdin and prints controlled verdicts or failures (the cwd is the scratch root, every path in the prompt is inside it, `expected.json` is absent from the scratch tree and the prompt, a failure is retried once, and one successful lane exits 1).
