# Plan 3 — `pr-diagrams` Skill and `explain-pr-changes --diagrams`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `explain-pr-changes` can render diagrams as Mermaid (inline) or draw.io (a PNG with the diagram embedded, uploaded with `gh pr create/edit --attach`), and promotion PRs reuse earlier PR bodies, diagrams and reviewers instead of regenerating them.

**Architecture:** A new skill `pr-diagrams` owns one tested bash script that resolves the target repository from `origin`, renders draw.io files to embedded-diagram PNGs in an isolated scratch repo, finds promotion sources and normalizes reviewers. There is no image branch and no upload API client: `gh --attach` (gh >= 2.101) uploads the PNG to GitHub user-attachments. The command `explain-pr-changes` gains arguments and a mode decision; its plugin bundles `pr-diagrams` and `draw-io`. The skill is gated by the plan 2 judge and its evals; the command is gated by its own command evals, run through a new `audit.py run-evals --eval-file` mode.

**Tech Stack:** Bash, `gh` >= 2.101, `git`, `jq`, Python 3 stdlib (`scripts/audit/audit.py`), drawio CLI via `skills/draw-io/scripts/convert-drawio-to-png.sh`.

**Spec:** [Roadmap](2026-10-24-00-roadmap.md) — Decisions 2, 12, 15, 16, 19; planner calls C1, C2; Global Constraints apply.

**Flag sources (verified read-only on 2026-10-25, not assumed):** `gh pr create --help` and `gh pr edit --help` (gh 2.101.0) document `--attach file`: it uploads an image or video, appends it to the body, or rewrites a body reference such as `![alt](./login.png)` to the uploaded asset; up to 50 files; on partial upload failure the PR is still created or updated, gh exits non-zero and the PR URL is still printed. `drawio --help` (draw.io 31.4.5, installed) documents `-e, --embed-diagram` ("includes a copy of the diagram (for PNG, SVG and PDF formats only)"); a PNG exported with it carries a `zTXt` chunk with keyword `mxGraphModel`, one exported without it has none (checked on a scratch file).

Branch: `feat/<yy-mm-dd>-pr-diagrams`. Depends on plan 2 (judge, `run-evals`).

## Review Focus

1. Re-run on an existing PR → head pushed first; open-PR lookup keeps only PRs whose full head repository (`headRepository.name` and `headRepositoryOwner.login`) is origin's (more than one left → stop); the PR is never its own reuse source (`--reuse-from` naming it, or any non-merged PR, is rejected before any PR write; recency is `merged_at`); a stacked base is never changed; the body is regenerated whole with at most ONE attached image, so a re-run never duplicates it. Pinned in Tasks 2-3.
2. `--diagrams=mermaid` (default) or `none` → nothing is uploaded (no `--attach`), a feature PR needs no `pr-diagrams.sh`, REPO is parsed inline (roadmap C1). The feature-head push, base fetch, base-from-open-PR, detached-HEAD and head == base guards are recorded behavior changes (Step 8); a promotion head (`develop`, `staging`, `main` by default) is never pushed, and one differing from `origin/<head>` stops the command. Pinned in Task 3.
3. A B→C promotion whose range holds earlier promotions into B and PRs merged directly into B → every related merged PR whose `base_ref` is B is a source (one copied verbatim, several consolidated), with its user-attachments image URLs and Mermaid blocks carried over in `mermaid` and `drawio` modes (`none` strips them, keeps other images). A diagram is authored only when warranted and no source body already holds one. A reuse title replaces an existing `[x → y] ` prefix instead of stacking it. Pinned in Tasks 2-3.
4. drawio render fails (CLI missing, export error), the script is unavailable, or gh is older than 2.101 → no image is uploaded, the caller's git index is untouched, and the PR still opens with an inline Mermaid fallback and a warning reported first. An `--attach` upload failing partway (gh exits non-zero but prints the PR URL) leaves the PR with the Mermaid fallback body and the failure reported first. The PNG carries the embedded diagram. Pinned in Tasks 2-3.
5. A missing script on `--reuse-from` or a promotion head stops the command before any push or PR write, in every diagrams mode. Any failed read (`related`, `reviewers`, `gh pr view`, `git fetch`) stops it before any PR write and names the call. PRs always open on `origin`'s repository. A relevant PR beyond the first page of a listing is still found, or the command stops with a named error. Two render inputs with the same basename never share one render. A bot reviewer (REST `user.type == "Bot"`) never reaches `--add-reviewer` or cancels the human reviewers. HTTP 403/429 on `related` stops with a named "rate limited" error. Any composed body (single-source included) over 65,000 characters is replaced by a link to its source PR(s) plus the overview, with the final message saying so, and a failing `gh pr create` or `gh pr edit` stops the command with the temp directory removed. Pinned in Tasks 2-3.

**Interfaces:**
- Target repository: always origin's. `pr-diagrams.sh repo` prints `<owner>/<repo>`: (tests only) env `PR_DIAGRAMS_REPO` when env `GH` is also set to a stub (any value other than `gh`; otherwise the env var is ignored with a stderr note), else parsed from `git remote get-url origin` (https, `git@github.com:` and `ssh://` forms, optional `.git`). A non-GitHub or unparsable origin URL exits 1 naming the URL. Every other subcommand resolves the repo once this way and calls `gh api repos/<owner>/<repo>/…` with the resolved names (never `{owner}`/`{repo}` placeholders; `gh api` has no `--repo` flag).
- `pr-diagrams.sh related <base> <head> [--exclude-pr N]` — runs `git fetch origin <base> <head>`, enumerates `origin/<base>..origin/<head>`, and per commit runs `gh api --paginate --jq '.[]' repos/<owner>/<repo>/commits/<sha>/pulls`: `--jq '.[]'` prints one JSON object per line, so several pages concatenate and the script parses the JSON lines (`jq -s`), never stdout as one document. Call volume: one paginated call per commit in the range, no cap (a release range of hundreds of commits costs hundreds of requests against the 5000-per-hour limit). A failure whose stderr contains `(HTTP 403)` or `(HTTP 429)` exits 1 with stderr `rate limited` naming the commit; any other failure exits 1 naming the commit. A failing `git fetch origin <base> <head>` exits 1 with git's stderr and no stdout. Keeps only merged PRs (`merged_at` non-null) other than `N` (open PRs, including the PR being created, are never sources), deduplicated by number. Stdout `[{"pr","title","head_ref","base_ref","merged_at"}]` sorted by `merged_at` descending then PR number descending ("most recent" always means this order); no related PR → `[]`.
- `pr-diagrams.sh reviewers <PR>... [--exclude LOGIN]` — per PR, two REST reads (not `gh pr view`, whose `reviews[].author` has no type field): `gh api --paginate --jq '.[]' repos/<owner>/<repo>/pulls/<PR>/reviews` (each review's `user.login` and `user.type`) and `gh api --jq '.users[]' repos/<owner>/<repo>/pulls/<PR>/requested_reviewers` (`login`, `type`; `teams` ignored). Only entries whose `type` is `User` are kept, so a `Bot` such as `copilot-pull-request-reviewer` and a review whose `user` is null are dropped. Stdout a JSON array of the union of logins, case-insensitively deduplicated, sorted, without `LOGIN` (compared case-insensitively, as GitHub logins are). A failed read exits 1 naming the PR.
- `pr-diagrams.sh render <file.drawio>...` — first, when the default converter is in use (`$DRAWIO_CONVERTER` unset), checks `command -v drawio` and otherwise exits 1 with stderr `drawio CLI not found` (the converter discards drawio's stderr and exits 0 when the CLI is missing, so the cause cannot be read from its output; a stub `$DRAWIO_CONVERTER` skips this check and owns its own failures). Before converting anything, two inputs with the same basename exit 1 naming both paths. Then copies the files into a `mktemp -d` directory that is `git init`ed and runs the converter with that directory as its working directory (the real converter runs `git add` on its outputs in its CWD under `set -e`: from the caller's repo on temp paths it would fail, from the caller's own directory it would stage into the caller's index), with the converter's stdout redirected to stderr (its status lines would corrupt the JSON on stdout), and requires for every input a freshly written `<name>.drawio.png` that is non-empty and starts with the PNG signature (the converter prints a failure and still exits 0, so its exit status proves nothing). The PNG embeds the diagram because the converter passes `drawio -e`. Only then copies the PNGs next to their sources and prints `[{"drawio","png"}]`; otherwise stderr names the file and the cause and exit 1 with nothing copied. The converter path is `$DRAWIO_CONVERTER` or, by default, `../../draw-io/scripts/convert-drawio-to-png.sh` relative to the script (valid in this checkout and in an installed plugin, which bundles both skills side by side; a copied-in single skill needs `draw-io` beside it or `$DRAWIO_CONVERTER`).
- Env `GH` (default `gh`) substitutes a stub in tests. Real `gh api` prints the HTTP error body to stdout, `gh: <message> (HTTP NNN)` to stderr and exits 1; the script captures every `gh` call's stdout and forwards nothing from a failed call, so its own stdout is only its documented JSON (nothing on failure). The test stub `GH` mirrors real `gh api` on HTTP errors exactly that way. The test stub `DRAWIO_CONVERTER` must behave like the real converter: it writes status lines to stdout and runs `git add` on its outputs in its working directory (failing if that directory is not a git work tree).
