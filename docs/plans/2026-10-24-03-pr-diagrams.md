# Plan 3 — `pr-diagrams` Skill and `explain-pr-changes --diagrams`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `explain-pr-changes` can render diagrams as Mermaid (inline) or draw.io (PNG on a shared `pr-diagrams` branch), and promotion PRs reuse earlier PR bodies, diagrams and reviewers instead of regenerating them.

**Architecture:** A new skill `pr-diagrams` owns one tested bash script that talks to the GitHub Contents API (no checkout, no per-PR branch). The command `explain-pr-changes` gains arguments and a mode decision; its plugin bundles `pr-diagrams` and `draw-io`. Both are gated by the plan 2 judge and evals.

**Tech Stack:** Bash, `gh`, `git`, drawio CLI via `skills/draw-io/scripts/convert-drawio-to-png.sh`.

**Spec:** [Roadmap](2026-10-24-00-roadmap.md) — Decisions 12, 15, 16; planner calls C1, C2; Global Constraints apply.

Branch: `feat/<yy-mm-dd>-pr-diagrams`. Depends on plan 2 (judge, `run-evals`).

## Review Focus

1. An agent creates branch `pr-diagrams/<N>` instead of folder `<N>/` on `pr-diagrams` → `ensure` fails loudly and `publish` refuses. Pinned in Task 2.
2. The command re-runs on an existing PR → re-publishing the same file updates it (no 422). Pinned in Task 2.
3. `--diagrams=mermaid` (the default) → no branch is created or pushed. Pinned in Task 3.
4. A B→C promotion whose range contains the feature PRs and the earlier A→B promotion PR → the A→B PR is reused as the single source. Pinned in Task 3.
5. A related PR has no diagram folder → its body still contributes. Pinned in Tasks 2-3.

**Files:**

**Interfaces:**
- `pr-diagrams.sh ensure` — if `origin` has no `refs/heads/pr-diagrams`, create it as an orphan from the empty tree (`git commit-tree 4b825dc642cb6eb9a060e54bf8d69288fbee4904 -m "pr-diagrams: init"`) and push; exit 1 if any `refs/heads/pr-diagrams/*` exists locally or on origin.
- `pr-diagrams.sh publish <PR> <file>...` — runs the same per-PR-branch check first (exit 1 naming the rule). Per file: GET `repos/{owner}/{repo}/contents/<PR>/<name>?ref=pr-diagrams --jq .sha` (404 = new) and PUT with that `sha` when present. On any API failure: stderr names the file, exit 1, no stdout. Success stdout `[{"file","path","url"}]`, url = `https://github.com/<owner>/<repo>/blob/pr-diagrams/<PR>/<name>?raw=true`.
- `pr-diagrams.sh related <base> <head>` — every PR whose commits are in `<base>..<head>` (`gh api repos/{o}/{r}/commits/<sha>/pulls`), with or without diagrams; stdout `[{"pr","title","head_ref","has_diagrams":bool,"files":[…]}]`.
- `pr-diagrams.sh list <PR>` — stdout `[{"path","url"}]`.
- Env `GH` (default `gh`) substitutes a stub in tests.

- [ ] **Step 1: Arguments.** `--diagrams=none|mermaid|drawio` (default `mermaid`, inline-only per C1), `--reuse-from=<PR>`; remaining arguments keep today's "Close $ARGUMENTS" behavior.
- [ ] **Step 2: Mode decision**, in this order:
  - (a) `--reuse-from=<PR>` → promotion from that single source: body and reviewers via `gh pr view <PR> --json body,reviewRequests,reviews`, diagrams via `pr-diagrams.sh list <PR>`.
  - (b) head is a long-lived branch (`PR_PROMOTION_BRANCHES`, default `develop,staging,main`) → run `related`. If any related PR's `head_ref` is itself in `PR_PROMOTION_BRANCHES` (an earlier promotion, e.g. the A→B PR when opening B→C), reuse the most recent such PR as the single source exactly like (a). Otherwise, one related PR → reuse it; several → consolidated summary from their bodies, linking existing diagrams, at most one new consolidated diagram. Title for reuse: `[<head> → <base>] <source title>`.
  - (c) otherwise → feature PR.
- [ ] **Step 3: Ordering.** Create/update the PR first (number needed). Mermaid: inline block only, no branch touched.
