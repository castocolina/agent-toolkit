# Plan 6 — New Skills: UI/UX Principles, Skill Updater, Artifact Judge Profiles

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship three things: a framework-agnostic `ui-ux-principles` skill carrying the eight UI/UX rules, a `skill-updater` skill that keeps skills, commands and agents current against their sources and current models, and judge profiles so `skill-judge` can grade commands and agents.

**Architecture:** `ui-ux-principles` is a checklist skill; `mui` and `design-system-starter` keep only framework or token specifics and point to it. `skill-updater` is a procedure plus one deterministic helper (`audit.py track`) that records review dates in the source registry; reasoning steps (path moved, research, "is this rule still valid for current models") stay in the skill text. Judge profiles reuse the D1-D8 schema, so `verdict.schema.json` and the merge code do not change.

**Tech Stack:** Markdown skills, `scripts/audit/audit.py` (Python 3, unittest), `skills/skill-judge`, `skills/agentskills-research`, pi lanes `my-referee-one` and `my-referee-two`.

**Spec:** [Known issues](2026-10-30-00-known-issues.md) sections 3, 5, 6 and the user's 2026-10-30 directives; [Roadmap](2026-10-24-00-roadmap.md) Global Constraints apply.

Branch: `feat/<yy-mm-dd>-new-skills`. Depends on plan 4 merged (judge, layout, evals harness). Task 3 changes `validate_entry`, which plan 5 Phase 1 also relies on (its `detect` runs `upstreams` over the registry): land plan 5 first, or rebase onto it, so `validate_entry` exists once on the base branch.

## Global Constraints

- Every artifact in English. No attribution lines in commits or PR text.
- Layout per `docs/conventions/skill-layout.md`: `SKILL.md`, `README.md`, `evals/evals.json`, `evals/trigger-queries.json`, fixtures in `evals/files/`; `SKILL.md` under 500 lines.
- Each new skill must grade 90 or more (Grade A) under `skill-judge` from both lanes; 80 is only the floor.
- Judge and review lanes: `my-referee-one` and `my-referee-two` in parallel, `my-referee-three` only as fallback when one fails. This is the user's ruling of 2026-10-28/30 and supersedes the one-plus-three pairing in roadmap Decisions 9 and 19 (recorded in Task 0 below). `my-coding` implements, never reviews. No native Opus in review. Build every pi command from `python3 scripts/audit/audit.py pi-cmd judge --model router-env/<lane>`; never hard-code the flags.
- Never edit `skills/gepetto` or `skills/datadog-cli`. Never put jev into a skill (roadmap Decision 19).
- Run `python3 scripts/build_plugins.py` and stage `dist/` before every commit that touches `skills/`, `agents/` or `commands/`.
- Local eval runner: `RUNNER="$(python3 scripts/audit/audit.py pi-cmd runner)"`.
- Every "90 percent" eval gate in this plan runs `run-evals ... --fail-under 0.9`; the default threshold is 0.8, so without the flag a 80-90 percent run exits 0.

## Review Focus

1. A rule is phrased as advice a model already follows (low knowledge delta) → each rule carries a concrete check, thresholds and examples sourced in `references/sources.md`, not a platitude. Pinned in Task 1 (Steps 2b, 3b) and evals.
2. `ui-ux-principles` duplicates `mui` or `design-system-starter` → pointers only, no copied rule text. Pinned in Task 2 (structure test).
3. `skill-updater` treats a moved upstream path as "no change" → path-missing is a distinct state that triggers research. Pinned in Task 3 (`track` tests) and its evals.
4. A model-dependent rule is kept forever → each reviewed artifact records the model it was last checked against (`reviewed_for_model`), and the per-rule findings go to `updates.md`. Pinned in Task 3.
5. A command or agent is judged with skill-only dimensions that do not apply → profiles rename and re-scope dimensions instead of failing artifacts for missing `evals/`. Pinned in Task 4.
