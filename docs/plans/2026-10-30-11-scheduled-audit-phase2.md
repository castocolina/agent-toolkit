## Review Focus

1. A triage answer injects text into a later step → the spec triage answer is the closed enum checked by `audit.py validate-triage`, its evidence is whitelisted (Task 3 Interfaces, B1), and free text never reaches the fixer prompt. Pinned in Task 3.
2. `rubric_stale` blocks every `ignore` (issue 4) → split into `spec_changed_this_run` (triage trigger) and `rubric_incomplete` (Task 3 Interfaces, B3). Triage runs only when `rubric_incomplete` and `structure_changed` are both false, so only they override `ignore`; a failing `rubric-check` fails `rubric`, which blocks `merge`. Pinned in Task 3.
3. A triage failure advances state → it fails the run without touching state (Phase 1 rule). Pinned in Task 3.
4. A skipped decision point is silent → one failure rule for every decision point (issue 8): a model error, an invalid enum, a timeout or a `decision-evidence.py` exit other than 0 and 2 fails the job, so the run fails without touching state (Focus 3), never "no change". Exit 2 (evidence rejected) is the one non-failure: `triage` succeeds with `rubric=update-rubric` and no model call (B1; `test_triage_evidence_exit_2_updates_rubric`). Ruling: a failed run, Phase 1's tested fail-safe (an invalid `recommendations.json` fails `upstream-report`), retried by the next due run; a failed triage has no PR to label `needs-human`. Pinned in Task 3.
5. The spike result contradicts an assumption → Task 1 records it, and Task 2 re-reads this table before editing anything.
